## What's new

- Replaced the scrolling volume-history animation with a live, 32-band logarithmic spectrum computed from current decoded PCM audio. A short 1,024-sample window at 16 kHz replaces the previous approximately 1.5-second visual history.
- Made the spectrum narrower, centered, and thinner to match the selected preview. Fast attack and gentle release follow the audio; silence, paused playback, and stale input settle toward the baseline. No random motion or preset waveform.
- FFT work runs on a single bounded worker. Busy analysis drops a visual sample rather than blocking playback. Stereo downmixing avoids cancelling strong opposite-phase content to silence.
- Added a persistent return-to-video button to the listening surface. Back closes an open channel/program/menu overlay first; Back from the listening surface restores video.
- Replaced the toolbar text-state button with a blue Material slide switch synchronized with the persistent button and actual listening state.
- Added an independent playback recovery banner. Sustained buffering shows a waiting message after a 1.5-second threshold evaluated by the one-second monitor (typically visible after about 2–3 seconds); actual recovery shows progress, exhausted sources show a retry countdown, disconnection shows network waiting, and successful playback briefly shows confirmation.

## Scope and privacy

This app-only update requires no server redeployment, new Groq key, or device re-pairing. It adds no permissions, external model, telemetry recipient, or dependency. Spectrum processing stays on the device and does not use a microphone, record audio, or automatically upload it. Existing AI caption consent remains separate.

Existing source penalties, cooldowns, retry budgets, and backoff remain in place. Playback sources, channel IDs, and database schema are unchanged. Video restoration can still require decoder/segment preparation; seamless recovery is not guaranteed.

## Channel identity detection is not enabled

This release does **not** add screenshot/OCR/AI verification of channel identity. Existing rejected-source filtering, explicit mismatch feedback, and manual source blocking remain available. Advertising or a missing logo is not treated as proof of a wrong channel. Automatic visual identification needs a separate accuracy and false-positive validation phase.

Startup checks centered on the current channel and its neighbors, source-address masking, and GPU enhancements remain separate backlog items.
