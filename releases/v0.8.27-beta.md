## Source addresses and presentation

Source selection displays a stable numeric source ID, enabled state, observed viewing score and media-check status. It does not display source URLs, hosts or IPs. The advanced endpoint-group editor is no longer a user-facing source action; existing internal endpoint metadata remains usable. Browser failure messages no longer echo URLs. Diagnostic event text redacts URLs and IPv4/IPv6 literals. This is UI masking, not URL encryption or protection against extraction by a device owner.

## Playback-aware source maintenance

- A cold launch schedules directory refresh and media checks after foreground playback has buffer headroom. Regular directory attempts are approximately hourly; unavailable/unverified sources are revisited approximately every 30 minutes. Android background scheduling is inexact. Checks that yield to playback can resume when headroom returns.
- Actual channel changes reprioritize the current channel's backup sources and its nearest +1/-1/+2/-2/+3/-3 channels using the current category's real channel-navigation order. Rapid uncommitted previews do not start a new maintenance sweep.
- Foreground playback starts background work with at least 12 seconds of buffer and keeps it running down to 8 seconds, provided estimated bandwidth has headroom when a bitrate is known. Buffering yields unrelated work. A stopped failed current channel can receive targeted repair; active buffering loads and the currently playing source are not probed in parallel.
- One low-priority source-maintenance worker replaces four parallel probes. A run has a 180-second cooperative deadline, media reads up to 24 MiB / 80 requests and separate directory reads up to 6 MiB / 20 requests. Targeted repair uses smaller 6 MiB media and 3 MiB directory budgets and a per-channel 60-second cooldown. These are application-read budgets, not exact network-billing limits; DNS/platform calls may outlive cooperative time checks.
- Foreground recovery requests targeted discovery when known lines are exhausted. Candidates still come from the app-managed reviewed catalogs, not an unrestricted web crawler. Requests have cancellation, budgets and cooldowns. Old directory omission alone no longer retires an admitted line; reappearing retired candidates can be revalidated before readmission. Disabled or identity-rejected sources are not silently re-enabled.
- As part of migration to app-managed maintenance, the obsolete automatic-source off preference is re-enabled once; source configuration is no longer a user setup requirement. Existing channel IDs, favorites, source IDs and source-data assets are retained.

## Stronger media checks and temporary availability

The checker downloads complete consecutive HLS segments within memory limits, parses video tracks and advancing sample timestamps using Android MediaExtractor, checks decoder availability, compares download time with media duration, and observes playlist advancement over target intervals. It does **not** instantiate a second player or perform full background decode/render. It cannot prove long-duration stability, content identity, rights or upstream independence. Large samples, byte-range playlists, cancellation and exhausted budgets remain unverified rather than failed.

Two completed all-admitted-source failure rounds, separated by at least two minutes and backed by recent successful network evidence, temporarily hide a non-current channel. Missing evidence, offline state, cancellation or budget limits cannot count as failure. Success restores availability without deleting favorites, IDs or ordering. Health is local to this installation/network and is invalidated after network changes. The selected channel is not forcibly exited. A channel drawer keeps its current membership/order while open and applies pending membership changes after closing/reopening, preserving focus and scroll position.

Media-check status and real watching scores remain distinct. Recent media failures rank below usable alternatives. Probes never grant near-perfect viewing scores or erase playback penalties. One uninterrupted actual-playback minute raises the watching score gradually and can clear playback cooldowns. Existing choppy-buffer/freeze recovery remains active.

## Native subtitles and optional text translation

- Media3 selects supported native Chinese text tracks first. Native cues suppress duplicate ASR; when native cues are absent for a grace period, the existing consented audio-caption fallback can resume.
- Native foreign text is translated only after the user manually enables the global native-subtitle translation switch and grants separate subtitle-text consent. The switch is disabled when global AI captions are off. Save/Cancel and consent-error focus rules are retained; there is no provider/model/key configuration for users.
- The new authenticated /v1/translate endpoint skips speech recognition, keeps the operator-controlled Simplified Chinese target and model, and shares the audio inference rate/day budgets, device proof, replay checks, concurrency leases and circuit breaker. No subtitle content is intentionally persisted in operator reports/databases/logs.
- One bounded latest-text queue coalesces cues; old-channel and stale results are discarded. Text requests are at least four seconds apart. Translation and speech are not promised instantaneous. Provider latency, limits and model availability require live measurement.
- Original subtitles remain available if translation fails or the endpoint has not been deployed. Bitmap subtitles can be displayed as supplied but are not OCR-translated. Changing caption preferences does not explicitly recreate the video player.

**The existing Cloud Run service has not been redeployed by this build task.** Its /v1/health check returned 200; /v1/translate returned 404 during the release check. Native foreign-language translation therefore needs the companion server update before it can work end to end. Other app changes and original native subtitles do not depend on that new route. The deployment package and services/update_caption_service.sh preserve the existing service's authorization mode and secret references. No API key or signing key is included.

## Playback notices

The channel-switch preview is about 10% larger, including type, logo and padding. Channel-switch and recovery/retry notices share a centered upper-screen anchor (40% of the safe viewport height). The channel preview takes precedence so the two notices cannot overlap. Safe insets and reading-area placement are retained.

## Validation

Builds passed. **111 Android JVM tests passed; 109 Python tests passed and 13 infrastructure-dependent tests were skipped (122 discovered). Lint: 0 errors, 122 warnings.** APK/AAB signatures, package/SDK values, no additional permissions, 16 KiB APK alignment and unchanged catalog/source/guide/logo/animation assets were verified. Six Android device-test cases were compiled but not executed. Exact results are in the versioned validation manifest. JVM tests cover selection order, small catalogs, availability hysteresis, network evidence, playback headroom, manifest progression, sustainable download checks, text consent and stale results. Python tests execute actual schema/queries and authenticated HTTP translation, shared quotas, tampering/replay rejection and text non-retention. Firestore/emulator-dependent tests may be skipped and are reported separately.

A device-test APK contains synthetic H.264/AAC media fixtures, generated locally with FFmpeg and checked with FFprobe, for real Android MediaExtractor checks of healthy, stale, missing/HTML and deferred/cancelled cases. It is built separately; fixtures and test dependencies are excluded from the release APK/AAB. It has **not been run on a device**: ADB initialization is blocked by a read-only Android home in the execution environment.

Physical TV/phone/tablet playback, local-network availability, focus/scroll behavior, source-repair latency, long-session stability, native cue delivery and deployed Groq translation remain unverified. No existing local channel is claimed repaired without measurements from the viewer's network.
